# Data_Analysis

# 基于大模型的故障日志诊断与分析系统

## 1. 项目简介

本项目是《智能数据分析》小组课程设计项目，旨在**复现并改进**一个全栈的**基于大模型的故障日志分析系统**。

该系统集成了前后端，用户可在前端输入一条故障日志。后端基于检索增强生成（RAG）技术，调用本地部署的大型语言模型（LLM）进行智能分析，最终返回结构化的**故障描述**、**故障原因**和**解决方案**。

- **项目名称：** 基于大模型的故障日志诊断与分析
- **任务目标：** 复现原始代码，并进行多项创新改进，提升系统的准确性和智能化水平。
- **当前状态：** **原始代码复现和所有代码改进任务均已完成。**

## 2. 技术架构

| **模块**     | **技术栈/组件**                          | **说明**                                                     |
| ------------ | ---------------------------------------- | ------------------------------------------------------------ |
| **后端**     | `Python3.10+`, `Django5`, `Django-Ninja` | 提供 `/chat`、`/history` 等 RESTful API 接口，负责核心业务逻辑。 |
| **前端**     | `Vue3`, `Vite`, `Element-Plus`           | 提供交互式 Web 界面，支持聊天历史和结果展示。                |
| **RAG/嵌入** | `bge-large:latest`, `Chroma`             | 使用 `bge-large` 嵌入模型将日志向量化，存储在 `Chroma` 向量数据库中进行检索。 |
| **大模型**   | `Ollama` (本地部署), `deepseek-r1:7b`    | 通过本地 Ollama 服务器调用大模型进行智能分析。               |

## 3. 功能实现与改进亮点

### 3.1 原始代码复现 (Part 01)

成功复现原始代码，实现了包含前端、后端、RAG 模块和大模型的全端智能分析系统。

- **核心模块：** `api.py` (API 接口), `services.py` (核心业务逻辑), `topklogsystem.py` (RAG 分析引擎)。
- **复现结果：** 在前端输入日志，可正确返回“故障描述、原因、解决方案”三项结果。

### 3.2 代码改进 (Part 02 - Part 05)

我们在原始系统的基础上，从用户体验、系统稳定性和智能化方面进行了以下改进：

| **改进点**            | **任务名称** | **描述**                                                     |
| --------------------- | ------------ | ------------------------------------------------------------ |
| **MarkDown优化**      | Part 02      | 引入 **MarkdownIt** 和 **DOMPurify**，将大模型输出的纯文本安全地渲染为 MarkDown 格式，提升前端排版和结果可读性。 |
| **多轮对话 & Prompt** | Part 03      | 重构会话管理，实现基于数据库存储的**多轮对话功能**。设计**五步分析模板**（问题理解、数据洞察等），实现结构化 Prompt 自动注入，并增加了**主题一致性检测**。 |
| **RAG优化**           | Part 04      | **知识库扩充：** 导入了开源组件、云服务商文档、历史故障报告等多样化知识。**线上检索：** 集成 **SerpAPI**，作为本地知识库的有效补充。 |

## 4. 部署

在开始部署前，请确保您的系统满足以下要求：

1. **操作系统：** Windows 10 (2004+) 或 Windows 11。
2. **虚拟化：** BIOS 中启用虚拟化（Intel VT/AMD-V）。
3. **WSL2：** 启用并安装 **适用于 Linux 的 Windows 子系统** 和 **虚拟机平台**，推荐安装 **Ubuntu 22.04.5 LTS**。
4. **模型服务：** 在 WSL 中安装并运行 **Ollama** 服务，并拉取所需模型（如 `ollama pull deepseek-r1:7b`）。
5. **依赖：** 安装 `Python 3.10+` 和 `Node.js / npm` 环境。

快速开始：

1. **启动 Ollama：** 在 WSL 中运行 `ollama serve`。
2. **启动后端：** 在后端项目目录下，激活 Python 环境并运行 `python manage.py runserver 0.0.0.0:8000`。
3. **启动前端：** 在前端项目目录下，运行 `npm install` 安装依赖，然后运行 `npm run dev`。
4. **访问：** 在浏览器中访问前端提供的地址（例如 `http://localhost:8082/`）。
